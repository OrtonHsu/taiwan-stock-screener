## 四階段目標

1. 資料穩定：歷史行情回補、統一交易日、缺漏偵測與異常警示。
2. 回測可信：公司事件、實際交易成本、樣本外測試。
3. 選股優化：同條件比較淨報酬、回撤與不同市場環境。
4. 盤後決策：每日候選股、觀察價位、風險及失效條件。

## 第一階段補充：逐交易日缺漏稽核（唯讀）

- 新增 `daily_gap_audit.py`：以 `TWSE`／`TPEX` 有足夠行情的**共同日期**作為比較基準，不將週末或未知休市日期直接認定為缺漏。
- 只檢查最新完整交易日仍有行情的股票，且只尋找該股票**已出現的首末日期之間**的缺日；停牌、暫停交易、零成交與轉板仍可能產生疑似缺日，必須人工確認。
- 列出市場不完整的日期，以及按缺日筆數排序的個股樣本；**不下載、不填價、不刪除、不寫入資料庫**。
- 使用 `DATABASE_URL`、只讀 Postgres 交易；GitHub Actions 的 `V2 Daily Missing Date Audit` 支援手動稽核，並於台灣時間每個工作日 23:46 排程唯讀檢查。GitHub 排程可能延遲或漏觸發。
- 指令：`python daily_gap_audit.py --lookback-days 120`；範圍限制 7～365 日。GitHub 執行紀錄 `DAILY_GAP_AUDIT` 及 Step Summary 有摘要。
- **限制**：如果兩個市場在同一日期完全沒有資料，單靠資料庫不能知道該日是真正休市或整日遺漏；市場筆數門檻無法證明逐檔資料完整。這一版只做可疑缺日偵測，正式修補需先核對交易所日曆、停牌及官方歷史報表。

離線測試：

```bash
python -m pytest -q test_screener.py test_recovery_status.py test_daily_gap_audit.py
```


## 第一階段補充：官方年度日曆與臨時休市核對（2026）

- \`tw_market_calendar.py\` 根據 [TWSE 115 年度開休市日期](https://www.twse.com.tw/holidaySchedule/holidaySchedule?queryYear=115&response=html) 維護已核對的 2026 年休市日。
- 2026-10-23 因薔琵颱風，上市及上櫃臨時全日休市，另依 [中央社 2026-10-22 報導](https://www.cna.com.tw/news/afe/202610220388.aspx) 及證交所相關公告核對，不能把當天當作漏檔。
- 新稽核同時辨識：① 兩個市場均達筆數門檻的比較日期；② 市場筆數不足日期；③ **官方預期交易日卻整日完全無上市／上櫃行情**；④ 已知休市日期反而有行情的可疑資料。
- 計算最新預期交易日時，以台灣時間 16:00 為截止點；16:00 前不將當天行情列為漏檔。排程晚於 16:00，若當日官方資料還沒發布，可能先顯示需查核的警示。
- 保守設計：**目前只支援核實的 2026 年**。若執行範圍跨到尚未核對的 2027 年，工作流程仍可檢查既有資料，但會明確報告 \`CALENDAR_UNVERIFIED\`，不猜測開盤日。
- 未來新增 2027 年度表或臨時休市事件時需核實來源後更新；年度日曆不代表臨時颱風休市已全部自動同步。
- 這項檢查**完全唯讀**；不更改每日行情更新、選股公式、回補排程或任何 Supabase 價格；個股停牌／零成交仍可能造成疑似缺日，待下一階段官方月歷史對照才能確認。


## 第一階段補充：逐檔疑似缺漏的官方月行情核對（手動小批次）

- 新增 \`official_gap_verify.py\`：只讀取 Supabase 近 120 天 TWSE/TPEX 行情與已核對 2026 年交易日，從「首末兩個已存交易日之間」挑選疑似缺日最多的上市、上櫃個股月份，每次最多 10 組（手動 workflow 預設 4 組）。
- 上市與上櫃個股月份交替挑選，避免疑似缺漏較多的一個市場占滿全部名額。
- 沿用現有 \`market_backfill.fetch_month / parse_month\`、\`tpex_backfill.get_month / parse_month\` 的官方月行情下載及日期檢查邏輯；每組股票月份查一次、間隔至少 2.5 秒，遇來源連線異常沿用既有重試。
- 分成兩種結果：① \`confirmed_missing_quote_dates\`（官方月資料有有效收盤價，但本地沒有）；② \`unresolved_dates\`（官方資料沒有可解析的有效收盤價，**不能宣稱一定休市、零成交或停牌**）。下載或驗證失敗則列為 \`OFFICIAL_GAP_FAILED\`，整批全失敗會明確失敗。
- GitHub Actions：\`V2 Official Individual Gap Verification\` **只支援手動觸發**；查看 \`OFFICIAL_GAP_SUMMARY\` 日誌或 Job Summary。沒有自動排程，不會大量打交易所 API。
- 全流程 \`conn.read_only=True\`，**只讀資料庫、不 INSERT/UPDATE/DELETE、不修改回補標記、不替任何缺日填價格**；這個驗證報告的官方有效行情缺漏日期，仍需另行設計經核對後的安全修復流程。
- 本次只是試點，無法全面核實 1,951 個疑似缺日，也無法證明未查到官方有效收盤價的日期真的沒有交易。
